## 二、接 Neon（你要做的）

### 1. 建项目

1. 打开 <https://neon.tech>，注册（GitHub 登录最快）
2. **New Project**，名字随便，比如 `gloss`
3. 区域选离你近的（同步延迟低些）：国内一般选 `Asia Pacific (Singapore)` 或 `Tokyo`
4. 计划选 **Free**（够用，别选付费）

### 2. 拿连接串

1. 进去后 Neon 会直接给你一个连接串，形状像：
   ```
   postgresql://user:password@ep-xxx.region.aws.neon.tech/neondb?sslmode=require
   ```
2. 整段复制

### 3. 给我

把连接串发我，或者自己填进 `.env.local`：

```
DATABASE_URL=postgresql://user:password@ep-xxx.region.aws.neon.tech/neondb?sslmode=require
```

## 四、已经做好的准备

### 1. 同步状态现在看得见了

**这是接数据库前最该补的一处。** 之前 `lib/sync.ts` 里所有错误都被 `.catch(() => {})`
吞掉——同步失败对用户完全不可见：书架只在本机、账户没更新，读者却毫不知情。

现在：

- `lib/sync.ts` 暴露 `SyncState`（`off` / `working` / `error`）与 `useSyncState()`
- 失败时底部出现提示条：「没有同步到你的账户。书架在这台设备上还是安全的。」+ 重试按钮
- 下次同步成功后提示条自动消失
- 日常阅读时不出现，不打扰

### 2. schema 与同步 SQL 已在本地的真 Postgres 上验证过

`npm run db:verify` 用 **PGlite**（真 Postgres 的 WASM 版，语义与 Neon 一致）跑完整流程，
15 项全过：

```
✅ 15 条语句执行完毕
✅ 8 张表：agent_tokens, articles, briefs, covers, free_usage, glosses, highlights, progress
✅ 15 个索引，含全部 6 个同步索引
✅ schema 可以重复执行（migrate 幂等）
✅ 文章写入：数据与正文都在
✅ 高亮写入正常
✅ 高亮更新（upsert 覆盖）正常
✅ 不带正文的更新：正文被保留（coalesce 生效）
✅ 删除走墓碑：deleted=true、正文清空
✅ pull（按 updated_at 取变更）正常
✅ 用户隔离：另一个用户看不到这些行
✅ free_usage（按金额计费）正常
✅ agent token 写入正常
✅ agent token 的 hash 唯一约束生效
✅ 封面写入正常
```

覆盖的关键点：**正文不会被空更新覆盖**（`coalesce(excluded.doc, articles.doc)`）、
**删除走墓碑而非物理删**（其他设备才知道）、**用户隔离**（`user_id` 过滤）。

### 3. 接到 Neon 后的体检脚本

`npm run db:check` 会逐项检查并给出结论：配置在不在、连不连得上、表齐不齐、
索引齐不齐、**写进去读得出来吗**（插一行再删掉）、`free_usage` 有没有 `usd` 列。
没配置时它直接打印三步指引。

## 七、常见问题

**`npm run db:migrate` 报连接错误？**
检查连接串是不是完整复制了（Neon 面板上有个复制按钮）。连接串要带 `?sslmode=require`。

**表建了但同步还是 503？**
跑 `npm run db:check`，它会指出缺什么。改完 `.env.local` 要重启 dev server。

**同步提示一直显示？**
说明 `/api/sync` 一直失败。打开浏览器开发者工具看 Network 里 `/api/sync` 的响应，
`npm run db:check` 也会指出问题。

**不想用数据库？**
也行。应用在没有数据库时完全可用——只是数据留在本机，登录不带来跨设备同步。
删掉 `DATABASE_URL` 就回到那个状态。
