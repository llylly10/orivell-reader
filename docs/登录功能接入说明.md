## 二、切换实例怎么做（已经做过一次）

`.env.local` 里的两个 key 决定用哪个实例。切换只需一条命令：

```bash
node scripts/switch-clerk-instance.js sk_test_xxxx dashing-prawn-4703
```

脚本会：验证 secret key → 读出该实例的社交连接 → 备份 `.env.local` → 写入新的
publishable key 与 secret key → 提示重启 dev server。

**两个 key 从哪来**：Dashboard → API Keys（<https://dashboard.clerk.com/~/api-keys>）

### publishable key 的规律（可能用得上）

Clerk 的 publishable key 就是前端域名的 **base64url**：

```
pk_test_ + base64url("dashing-prawn-4703.clerk.accounts.dev$")
```

注意是 **base64url 不是 base64** —— 标准 base64 会多一个 `=`。

### 两个坑

1. **无效的 secret key 会让 dev server 直接死掉**。Clerk 中间件校验失败会抛异常，
   进程瞬间退出，日志里还看不到明显报错。启动后如果端口不通、页面连不上，
   先检查 secret key。
2. **API 改不了实例设置**。`PATCH /v1/instance` 返回 204 但会静默忽略
   `social` / `display_config` 字段；FAPI 需要 Dashboard 的浏览器会话 cookie。
   社交连接和应用名只能在 Dashboard 里改。

### 端到端登录怎么验证的

用的是 Clerk 官方 `@clerk/testing` 的同一套机制：

1. Backend API 建一个 `+clerk_test` 测试用户
2. 签一个 sign-in token（ticket 策略）
3. 拦截所有 Clerk Frontend API 请求，附加 `__clerk_testing_token`，绕过 Cloudflare Turnstile 机器人检测
4. 在页面里 `Clerk.client.signIn.create({strategy:"ticket"})` → `setActive()`

⚠️ 这个过程会在 Clerk 实例里留下测试用户。脚本跑完已清理，当前实例用户数 = **0**。

## 七、常见问题

**登录页空白？**
检查 `next.config.ts` 里有 `allowedDevOrigins: ["127.0.0.1", "localhost"]`。没有它，Next.js 会拦截 `/_next/hmr` 的 WebSocket，前端 bundle 不更新，Clerk 组件就不会挂载。

**Clerk 组件还是英文？**
Clerk 的 localization 是跟随项目语言的。项目语言取自 `localStorage["gloss:lang"]`，没有就跟随 `navigator.language`。在登录页右上角切语言即可。

**「登录 My Application」？**
Dashboard 里把应用名改成 Gloss。或者不管它——代码里已经用 localization 覆盖成「登录 Gloss」了。

**登录后控制台报 503？**
数据库没配。属于预期，见第六节。

**dev server 启动后端口不通、页面连不上？**
多半是 `CLERK_SECRET_KEY` 无效。Clerk 中间件校验失败会直接抛异常把进程杀掉，
日志里还看不到明显报错。用 `node scripts/switch-clerk-instance.js <secret-key> <domain>`
重新写入正确的 key。

**怎么确认当前用的是哪个 Clerk 实例？**
```bash
# publishable key 解出前端域名
node -e "console.log(Buffer.from(process.env.PK.replace(/^pk_(test|live)_/,''),'base64url').toString())"
# 或直接看 .env.local
```
