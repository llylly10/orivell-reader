## 二、你需要做的：启用 GitHub 登录（1 分钟）

开发实例用 Clerk 预置的**共享 OAuth 凭证**，不需要自己申请 GitHub App、不需要 Client ID/Secret。

1. 打开 <https://dashboard.clerk.com>
2. 选你的应用 **discrete-pug**（开发实例）
3. 左侧 **Configure → SSO Connections**
4. **Add connection** → 选 **For all users**
5. Provider 下拉选 **GitHub**
6. **不要**打开「Use custom credentials」（开发实例用共享凭证）
7. 点 **Add connection**

完成后回到 `http://localhost:3100/sign-in` 刷新，**「使用 GitHub 登录」按钮会自动出现**——不需要改任何代码。Clerk 的 `<SignIn />` 组件只渲染实例已启用的 provider。

### 生产环境（将来部署时）

开发实例的共享凭证不能用于生产。届时需要在 GitHub → Settings → Developer settings → OAuth Apps 建一个应用，Homepage URL 填你的域名，Authorization callback URL 填 Clerk Dashboard 里显示的回调地址，然后把 Client ID / Secret 填回 Dashboard 并打开「Use custom credentials」。

### 端到端登录怎么验证的

用的是 Clerk 官方 `@clerk/testing` 的同一套机制：

1. Backend API 建一个 `+clerk_test` 测试用户
2. 签一个 sign-in token（ticket 策略）
3. 拦截所有 Clerk Frontend API 请求，附加 `__clerk_testing_token`，绕过 Cloudflare Turnstile 机器人检测
4. 在页面里 `Clerk.client.signIn.create({strategy:"ticket"})` → `setActive()`

⚠️ 这个过程会在 Clerk 实例里留下测试用户。脚本跑完已清理，当前实例用户数 = **0**。

## 七、常见问题

**登录页空白？**
检查 `next.config.ts` 里有 `allowedDevOrigins: ["127.0.0.1", "localhost"]`。没有它，Next.js 会拦截 `/_next/hmr` 的 WebSocket，前端 bundle 不更新，Clerk 组件就不会挂载。

**Clerk 组件还是英文？**
Clerk 的 localization 是跟随项目语言的。项目语言取自 `localStorage["gloss:lang"]`，没有就跟随 `navigator.language`。在登录页右上角切语言即可。

**「登录 My Application」？**
Dashboard 里把应用名改成 Gloss。或者不管它——代码里已经用 localization 覆盖成「登录 Gloss」了。

**登录后控制台报 503？**
数据库没配。属于预期，见第六节。
